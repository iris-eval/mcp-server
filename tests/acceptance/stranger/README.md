# The stranger — the agent-native acceptance harness

A fresh headless Claude Code session, with no prior instruction about Iris, is asked to evaluate three real agent outputs with Iris and say which must not ship. It runs on the packed or published artefact at every release, never on a checkout, and it is graded by fixed rules over the session stream — never by re-reading the transcript with a model.

```bash
# the published release
node tests/acceptance/stranger/run.mjs --spec @iris-eval/mcp-server@0.9.0 --out <private record dir>

# a pre-release tarball (the MCP config the agent writes is rewritten to it; the substitution is recorded)
npm pack && node tests/acceptance/stranger/run.mjs --tarball ./iris-eval-mcp-server-0.9.0.tgz --out <dir>

# one phase
node tests/acceptance/stranger/run.mjs --spec … --phase http
```

**Isolation (the arc-zero verifier's amendments, all in code):** a never-used directory per phase holding only `outputs/` — the three transcripts `t-01`, `t-07`, `t-13` from `tests/fixtures/real-transcripts/` with their `metadata` (the answer key) stripped, generated by the script, never hand-copied; the script lives outside the directory; a scratch `IRIS_HOME` per phase, also outside it; `claude -p` in a never-used directory (no CLAUDE.md, no project settings, an empty per-directory memory; `--bare` is not used because it also skips the login) with `--permission-mode dontAsk`, `--strict-mcp-config` and an allowlist of single-command forms (`npx`, `npm`, `node`, `curl`, `ls`, `cat`, the file tools, web fetch and search, the `iris-eval` tools); both judge key variables are removed from the child environment.

**The MCP path in two phases.** A headless session cannot attach a server to itself mid-run, so phase 1 discovers the install and writes `./mcp-config.json` (rows A1, A3); phase 2 starts from that exact config with the package spec rewritten to the artefact under test (rows A2, A4–A7); A8 is a driver turn on the resumed phase-2 session asking for the judge with no key. One HTTP run with no servers attached (rows H-*).

**Rows and what counts.** A1 and A3 on tool-call evidence (a discovery fetch then a config write; the server listed as connected). A5: zero `IRIS_INVALID_ARGUMENT` results, or one followed by a corrected call. A7: at least one `log_trace` and a resource followed. A2, A4, A6, A8 on the agent's words with the matched line quoted: the first Iris call precedes any README read after connection and the final text distinguishes `score` from `passed`; three `evaluate_output` calls and no judge call before A8; `no_pii` for output 2, `no_silent_tool_failure` with "still passed" for output 3, "passed" plus a named unjudged question for output 1; after the driver, at least one `IRIS_JUDGE_NOT_ENABLED` result, zero web calls, and the final text naming the key variable and the restart. Success is every row within twelve tool calls after connection with no README read after connecting.

**Records.** Each phase writes `<phase>.jsonl` (the stream), `<phase>.stderr.log` and `<phase>.json` (model id, cost, wall time, tool calls, denials, README reads, the substitution note); `rows.json` carries the graded rows with one evidence line each. Records are evidence for a public claim and carry the model's reasoning and per-run cost, so they live in the private strategy record until the maintainer decides to publish them; nothing under `tests/acceptance/stranger/records/` is committed here.

**Cost.** About one to two dollars per phase on the account that runs it. A judge key is never required and never passed; the A8 row exists precisely because it is absent.
